## What was done

The task-ledger data model (T-00014, ported to Rust in
`code/aiosh-rust/aiosh-core/src/ledger.rs`) is now a first-class
**production CLI surface** on the shipping Rust stack:

```
aiosh task status                          → live TASK_STATE.json
aiosh task check                           → ledger invariants (10,000 tasks)
aiosh task rebuild                         → recompute state from event log
aiosh task done <id> [--note S]            → no-skip-complete, advance by 1
aiosh task block <id> --reason R           → block current task
aiosh task unblock <id> --reason R         → unblock (pointer back)
aiosh task skip <id> --reason R            → human override (pointer_reset event)
```

Registered in `aiosh-cli/src/main.rs` alongside `status/run/audit/grant/
pentest/classify` (discoverable via `aiosh --help`). Every command emits
the same JSON envelope (`ok / subcommand / data | error`) as the other
subcommands.

## Cross-substrate parity (instruction 2)

The ledger lives in `docs/tasks/` (canonical JSON files, not SQLite), so
parity = both implementations read/write `TASK_STATE.json` +
`COMPLETIONS.jsonl` with identical semantics. Proven **both directions**
and asserted in CI:

- Python `tools/task_ledger.py` reads Rust-written state/events → same
  `next_task`, `completed`, `last_event_seq`.
- Rust `aiosh task status/check` reads Python-written state/events → same
  values; no-skip and invariant checks match.
