# T-00009 — Retention security review

**Completed:** 2026-08-21
**Scope:** `rotate` / `verify_full` / `seen` in
`code/aiosh-mcp/aiosh_mcp/retention.py` and `code/aiosh-cli/src/retention.ts`,
plus their MCP/CLI surfaces (`server.py:aios_audit_rotate|seen|segments`,
`cli.ts:audit rotate|seen|segments|verify --full`).

## 1. Injection review

| Vector | Finding |
|---|---|
| SQL injection | All queries parameterized (`?` / `@name`). Table name is a module constant. `seen()` interpolates the hash into a `WHERE hash = ?` parameter, not into SQL text. PASS |
| Command injection | Retention code spawns no subprocesses. PASS |
| JSON injection | Archive lines are produced by the proven canonical serializers (`json.dumps(sort_keys)` / `canonicalJson`), which escape strings. `seen(exact)` matches `"hash":"<h>"` inside a canonical line; `h` is lowercased/trimmed hex, no wildcard semantics. PASS |
| Bloom item input | Item is always a row `hash` (sha256 hex) or the caller-supplied hex in `seen()`; fed through `sha256(f"{i}:{item}")` — no interpretation of item content. PASS |

## 2. Path traversal review

- Archive path is **never** built from user input: `segment-<id>.jsonl` under
  the archive root, where root = `dirname(db)/audit-archive` (derived from
  `PRAGMA database_list`) or the internal default. No user string enters the
  path. PASS
- `archive_root` parameters exist on the library API but are **not exposed**
  through any MCP tool or CLI flag; MCP/CLI always use the DB-derived default.
  Even when supplied, only `basename()` fallback joins are used in
  `seen`/`verify_full`, so a bogus root cannot escape via `../` in a stored
  path… with one caveat below.
- **Caveat (accepted, low):** `verify_full`/`seen` read the file at the
  `archive_path` recorded in `audit_segments`. If an attacker already has
  write access to `audit.db`, they could point a segment at an arbitrary
  readable file; the sha256 pin then fails verification loudly instead of
  serving the wrong content, and DB write access already implies total
  compromise. No additional gate added; documented.

## 3. Covert-erasure abuse review

- **Rotation refuses on a broken chain** (both substrates) and records the
  refusal as an audited row — rotation cannot be used to launder tampering.
  Proven by smoke R4 (Python) and mirrors TS logic (`retention.ts:rotate`
  verify-first branch).
- **Archive-before-delete:** the JSONL file is written and `os.replace`d /
  `renameSync`d to its final name *before* the DB transaction deletes rows;
  the transaction (segment insert + delete + rotate row) commits atomically.
  On transaction failure the orphan archive file is unlinked (Python) /
  best-effort unlinked (TS). A crash between file write and commit leaves an
  orphan file but an untouched DB — no data loss.
- **Every rotation is itself an in-band `audit.rotate` row** (O-2) carrying
  `segment_id, row_count, first/last ids, head_hash, archive_path,
  archive_sha256` — erasure of history is observable in the chain itself.
  `c3=true` marks it irreversible-class.
- **MCP surface is PEP-gated:** `aios.audit.rotate` is dispatched with
  `require_grant=True`; no-grant calls are refused at the PEP gate and the
  refusal row is written. Proven by smoke R7 (`gate=pep`, then granted
  rotation succeeds). Classifier gate runs first per ADR-0035 §D-4.
- **CLI surface is ungated by design:** `aiosh audit rotate` is the user's
  own shell (same posture as `grant create/revoke`); host-level access to
  the CLI is the trust boundary. Documented in SPEC §5.
- **Bloom filters cannot hide membership:** `seen()` checks the live table
  by exact hash first, then bloom (no false negatives); `exact=True`
  confirms against the archive file. A malicious operator deleting an
  archive file breaks `verify --full` (sha256/missing-file alarms), which
  is the tamper-evidence guarantee, not the bloom filter.

## 4. Denial-of-service notes (accepted for Sprint 3)

- `rotate` reads all to-be-archived rows into memory in one query; a ring
  with millions of un-rotated rows would spike memory. Mitigation: rotate
  periodically (runbook §6 recommends ~5k-row threshold with `--keep 1000`).
- `verify --full` loads each archive file fully. Same periodic-rotation
  mitigation keeps individual files small.
- `tail()` is capped at 1024 rows (pre-existing), `seen(exact)` scans only
  bloom-positive segments. No unbounded user-facing reads introduced.

## 5. Cross-substrate parity (tamper-evidence invariant)

- `audit_segments` DDL, archive line format (canonical JSON of
  `to_dict()`/`archiveDictFromRow`), bloom index derivation, and rotation
  row proto are identical by construction; smoke R6 proves **TS rotates →
  Python verify/verify_full/bloom/seen all pass**, and R1–R3 prove the
  reverse direction (Python rotates → TS CLI `audit verify --full` passes
  with `archive_checked` > 0).

## Verdict

No open bypass. Retention is safe to operate under the documented cadence.
Residual accepted risks: archive_path trust under full-DB compromise
(inherent), and in-memory rotate for very large rings (operational cadence
mitigates).
