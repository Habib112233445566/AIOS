# T-00092 — documentation component: Specification

**Status:** LOCKED (2026-08-22) · Implementing artifact:
`tools/check_task_docs.py` · Reviewable without reading implementation.
Research basis: `T-00091-research.md` (decisions D1–D4).

## 1. Purpose & scope

One deterministic, stdlib-only checker that makes the Task-Ledger-Control
doc set rot-proof, mirroring the proven `tools/check_security_policy.py`
pattern (PASS/FAIL lines, collect-all failures, exit 0/1). Scope locked
to the ledger doc set (D1): `docs/SPEC-TASK-LEDGER.md`,
`docs/tasks/MASTER_TASK_LEDGER.md`, `docs/tasks/GOALS.md`,
`docs/README.md`.

## 2. Interface (reused, nothing new invented)

| Item | Source |
|---|---|
| CLI form `python3 tools/check_task_docs.py`, no args | parity w/ check_security_policy.py |
| Output `[✓]/[✗] <label>` + final `PASS: task docs criteria (C1..C6)` | parity |
| Exit: 0 all-pass; 1 with every failure listed (never fail-fast) | parity |
| Repo root = `Path(__file__).resolve().parents[1]` | parity |
| Deps: stdlib only (`pathlib/re/sys`) | zero-new-deps law |

Module surface (scaffold contract):
`CHECKS: list[str]` (labels C1..C6), `def main() -> int`, plus one pure
helper per check: `check_c1_spec_exists() -> tuple[bool,str]` …
`check_c6_no_volatile_counts() -> tuple[bool,str]`. Bodies raise
`NotImplementedError` until T-00094.

## 3. Checks (exact contract)

- **C1 spec-health:** SPEC exists; zero `TODO` markers.
- **C2 component sections:** headings `### 8.1` … `### 8.6` present,
  each carrying its frozen epic range
  (`T-00031..T-00040, T-00041..T-00050, T-00051..T-00060,
  T-00061..T-00070, T-00071..T-00080, T-00081..T-00090`).
  Additional `### 8.x` sections allowed (monotonic growth, D3-safe).
- **C3 referenced paths exist:** every backticked repo-relative path in
  SPEC resolves in-tree, EXCLUDING (a) lines inside fenced code blocks,
  (b) the documented example placeholder `evidence/x.md`.
- **C4 phase map integrity:** `MASTER_TASK_LEDGER.md` table rows equal
  the 10 phases derived from `MASTER_TASK_LEDGER.jsonl`
  (name match; `T-<first> .. T-<last>` equal to min/max id per phase).
  Generator-owned file is READ here, never written (D3).
- **C5 index health:** `GOALS.md` and `docs/README.md` contain no TODO;
  README's relative markdown links resolve.
- **C6 no volatile counts in LIVING docs:** SPEC/GOALS/README must not
  contain `CI <n>/<n>` patterns (suite-count rot observed in research);
  frozen evidence files are exempt by scope.

## 4. Failure path

Any violated check → its `[✗]` line prints the concrete offending
artifacts (missing path list, mismatched phase row, offending line).
Process exits 1 AFTER evaluating all checks. Missing/unreadable input
file = that check fails with the named path; never an exception leak.

## 5. Persistence & audit effects

Checker is strictly read-only: no file writes, no DB access, no audit
rows of its own (nothing consequential happens). Its CI invocation
leaves a log under `/tmp/aiosh-ci-*.log` via the standard runner;
ledger-pointer advancement continues to be audited exclusively through
`aiosh task done` as today.

## 6. Happy-path proof obligation (for T-00094)

Running against the current tree MUST exit 0 with all six `[✓]`.
Any red = either a real doc defect (fix the doc) or a checker bug (fix
the checker); both outcomes recorded in T-00094 evidence.
