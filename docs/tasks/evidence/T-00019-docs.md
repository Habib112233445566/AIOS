## Method (no fabrication)

Every claim in the spec was verified before being written:

1. Implementation read end-to-end:
   `code/aiosh-rust/aiosh-core/src/ledger.rs`,
   `code/aiosh-rust/aiosh-cli/src/main.rs::cmd_task`,
   `tools/task_ledger.py`.
2. Behavior exercised on **scratch copies** of the ledger
   (`AIOSH_TASKS_DIR` → temp dir; live ledger untouched):

```
$BIN task done 25 --note x   (while next_task=19)
→ {"error":"NO-SKIP violation: attempted to complete T-00025 but
    next_task is T-00019. Complete T-00019 first.","ok":false,
   "subcommand":"task done"}

$BIN task block 20 --reason t   (while next_task=19)
→ {"error":"can only block next_task (T-00019), got T-00020",
   "ok":false,"subcommand":"task block"}
```

3. Limitation L3 verified empirically in Rust and by code inspection in
   Python (`rebuild_state` computes `next_task = max(completed)+1` in
   both): after `skip 19` → live pointer 20 → `task rebuild` → pointer
   back at 19. Documented as a known limitation + decision needed.
4. Limitation L2 verified empirically: invoking the binary by absolute
   path without `AIOSH_TASKS_DIR` stats
   `/content/AIOS_MERGED/code/docs/tasks/MASTER_TASK_LEDGER.jsonl`
   (default `current_exe()` heuristic misses the filename component).
