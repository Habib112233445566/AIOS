# T-00152 — CI Smoke Orchestration / configuration: SPECIFICATION

**Date:** 2026-08-25
**Feature:** CI Smoke Orchestration configuration (`CiConfig`)

## 1. Feature summary

Following the precedent established in the Task Execution domain (T-00052), CI Smoke Orchestration configuration will adopt Twelve-Factor III alignment. All configuration knobs live entirely in environment variables with built-in defaults. No configuration files are used. Values are loaded fresh at operation start, and invalid values produce loud errors naming the specific variable.

## 2. Interfaces reused vs new

| Reused | Why |
|---|---|
| Environment variables | Standard Twelve-Factor III alignment; no config files |
| Bounds validation pattern | Matches `LedgerConfig::from_source` |
| `aiosh ci config` action | Parity with `aiosh task config` |

| New | Shape |
|---|---|
| `CiConfig` struct (Rust) | Parsed representation of all `AIOSH_CI_*` knobs |
| Python Config Dictionary | Parallel resolution logic for `ci_run.py` |

## 3. Configuration Knobs

The following knobs will be recognized. Precedence is always `environment > default`.

| Env Var | Type | Default | Constraint / Floor |
|---|---|---|---|
| `AIOSH_CI_RESULTS` | string | `/tmp/aiosh-ci-results.json` | Must not be empty |
| `AIOSH_CI_MAX_FILE_BYTES` | integer | `1048576` (1MB) | `>= 1024` |
| `AIOSH_CI_TIMEOUT_DEFAULT_S` | integer | `900` | `>= 10` |
| `AIOSH_CI_LOAD_RETRIES` | integer | `3` | `>= 0` |
| `AIOSH_CI_RETRY_SLEEP_MS` | integer | `500` | `>= 10` |

*(Note: The suite registry `SUITES` in `ci_suites.py` remains Python code by design and is outside the scope of these scalar scalar execution bounds).*

## 4. Inputs / Outputs & Actions

**Action: `config`**
- **CLI (`aiosh ci config`)**: Prints a JSON object representing the effective configuration.
- **MCP (`aios.ci` action="config")**: Returns the same JSON object.
- **Output format**: One entry per knob detailing the resolved `value` and its `source` (`"env"` or `"default"`).
  ```json
  {
    "max_file_bytes": {"value": 1048576, "source": "default"},
    "load_retries": {"value": 5, "source": "env"}
  }
  ```

## 5. Error Cases & Exit Codes

| Case | Behavior | Audit Effect |
|---|---|---|
| Unparseable integer (e.g. `AIOSH_CI_LOAD_RETRIES=foo`) | Loud refusal: `invalid AIOSH_CI_LOAD_RETRIES='foo': must be integer` (Exit 2) | Emits `error` row if triggered during a gated `check` invocation. |
| Out of bounds (e.g. `AIOSH_CI_MAX_FILE_BYTES=100`) | Loud refusal: `invalid AIOSH_CI_MAX_FILE_BYTES='100': must be >= 1024` (Exit 2) | Same. |

## 6. Persistence & Audit Effects

**Persistence:**
Configuration resolution itself is read-only. It modifies the runtime behavior of the orchestrator and the CI service but writes no state.

**Audit Effects:**
Calling `aiosh ci config` is a read-only query and writes no audit rows, identically mirroring `aiosh task config`. If bad configuration breaks a gated `check` operation, the resulting exit will emit an honest `error` audit row naming the configuration failure as the reason.
