# T-00142 — CI Smoke Orchestration / MCP/API surface: SPECIFICATION

**Date:** 2026-08-25
**Feature:** CI Smoke Orchestration MCP/API surface (`aios.ci`)

## 1. Feature summary

The `aios.ci` tool exposes the CI Smoke Orchestration core service to S-rank agents over the Model Context Protocol (MCP). It allows agents to autonomously query the outcome of a CI run, view human-readable reports, and inspect specific failure logs without dropping down to raw terminal commands.

## 2. Interfaces reused vs new

| Reused | Why |
|---|---|
| `aiosh_core::ci::load_summary_with_retry` | Core parsing and validation logic (single source of truth). |
| `aiosh_core::ci::human_report` | Core formatting for the `show` action. |
| Audit Ring (`aiosh_core::audit`) | For ADR-0035 honest audit row emission on `check`. |

| New | Shape |
|---|---|
| `aios.ci` MCP Tool | JSON RPC endpoint exposed by `aiosh-mcp`. |
| MCP Schema | `{"type": "object", "properties": {"action": {"type": "string", "enum": ["check", "show", "failures"]}}, "required": ["action"]}` |

## 3. Inputs / Outputs

**Inputs (JSON):**
- `action`: String, exactly one of `"check"`, `"show"`, or `"failures"`.
- `file`: (Optional) String, explicit path to the CI summary JSON artifact.

**Outputs (JSON):**
- **Success:** `{"ok": true, "tool": "aios.ci", "result": <string report or JSON payload>}`. For `show` and `failures`, the `result` is the human-readable string. For `check`, the `result` contains the boolean verdict and summary counts.
- **Failure:** `{"ok": false, "error": "<error message>"}`.

## 4. Error Cases & Behavior

| Case | MCP Output | Audit Effect |
|---|---|---|
| Artifact missing / unreadable / >1MB cap | `{"ok": false, "error": "ci-service: could not stat..."}` | Emits `error` row. |
| Invalid JSON / Math incoherent | `{"ok": false, "error": "parse error: ..."}` | Emits `error` row. |
| Invalid action argument | `{"ok": false, "error": "unknown action"}` | None (rejected before core). |
| `check` with failing suites | `{"ok": true, "result": "ci-check: FAIL..."}` | Emits `failure` row. |

## 5. Persistence & Audit Effects

**Persistence:**
The MCP API surface is strictly read-only regarding the filesystem. It parses the artifact generated by the CI orchestrator but never modifies it.

**Audit Effects (AIOS-specific):**
Per ADR-0035 §F-2, consequential actions must write an honest audit row. 
When the `action` is `check`, or when the artifact load fails, the MCP server will delegate to the core service's error-handling path to write an audit row to the SQLite WAL, exactly as the CLI surface does. `show` and `failures` are pure observational queries and do not write audit rows, matching CLI behavior.
