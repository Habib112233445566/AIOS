# T-00692 — Repository Health / documentation: Specification

## 1. Specification Overview
This specification formalizes the operator and agent documentation structure, CLI and MCP interfaces, configuration schemas, human-readable summary formatter (`format_repo_health_summary`), and invariant boundaries for Repository Health in AIOS.

## 2. Interface References & Specifications

### A. CLI Commands Reference (`aiosh-cli`)
- **`aiosh repo health [--json]`**:
  - Performs git working tree inspection, workspace file bounds verification (16 MiB default), and security governance policy audit.
  - Formats output via `format_repo_health_summary` for console display, or outputs raw JSON when `--json` is specified.
- **`aiosh repo check [--json]`**:
  - Alias for `aiosh repo health`.

### B. MCP Tools Reference (`aiosh-mcp`)
- **`aios.repo.health`**:
  - Arguments: `repo_path` (string, optional, default `"."`).
  - Returns: `{ "repo_path": string, "timestamp_utc": string, "overall_status": string, "total_checks": u32, "passed_checks": u32, "warn_checks": u32, "failed_checks": u32, "skipped_checks": u32, "checks": [...] }`.
- **`aios.repo.check`**:
  - Alias for `aios.repo.health`.

### C. Human-Readable Formatter (`format_repo_health_summary`)
- Signature: `pub fn format_repo_health_summary(report: &RepoHealthReport) -> String`
- Layout:
  - Header: `AIOS Repository Health Report ([<STATUS>]):`
  - Repo root: `  Repository Root: <path>`
  - Timestamp: `  Timestamp (UTC): <timestamp>`
  - Check entries: `  [<STATUS>] <name> (<check_id>) - <message> (<duration_ms>ms)`
  - Optional details: indent by 4 spaces for each detail item (up to 50 items).
  - Summary: `  Summary: <total> total (<passed> pass, <warn> warn, <failed> fail, <skipped> skip)`

### D. Documentation Invariants
- `docs/README.md` maintains `## Repository Health (T-00611..T-00710)` section.
- Backticked file and code paths resolve to valid repository paths.
- Avoid volatile CI/test count snapshots per doc invariant C6.
- Evidence references resolve within `docs/tasks/evidence/`.
