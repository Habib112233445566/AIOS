# T-00102 — Task Ledger Control / recovery & validation: SPECIFICATION

Date: 2026-08-23 · Status: SPEC v1.0 (implements decisions D1–D5 from
`docs/tasks/evidence/T-00101-research.md`)
Reviewable WITHOUT reading the implementation (per task acceptance).

## 1. Feature summary

A new **read-only ledger action `validate`** that compares the live
`TASK_STATE.json` against a deterministic replay of the append-only event
log and reports integrity findings. It is strictly **report-only**: the only
repair path remains `task rebuild` (SPEC §4/T-00022 §6, lock-free by design).
`validate` never mutates state, events, or evidence.

AIOS-specific surface extension (marked per instructions): the `validate`
action name and findings schema are AIOS conventions; no upstream standard
is claimed.

## 3. Inputs / outputs

### Input
None beyond resolved paths (same resolver as every other action:
`$AIOSH_TASKS_DIR` → ancestor walk → loud error). No operands accepted;
a stray operand is a usage refusal exactly like `metrics` (T-00085 parity).

### Output — stable ADDITIVE key set (mirrors metrics promise, T-00082)

```
data: {
  consistent: bool,            // true iff zero FATAL findings
  checks: {
    state_vs_events: {status: "ok"|"fatal", detail: str|null,
                      fields: [str,...]},          // G1 drift
    event_seq:       {status: "ok"|"fatal", detail: str|null},   // G2 seq integrity
    pointer_range:   {status: "ok"|"fatal", detail: str|null},   // G5 sanity
    evidence:        {status: "ok"|"warning", missing: [str..],
                      orphans: [str..]}                         // G3+G4
  },
  replay: {next_task: int|null, completed: int, blocked: int,
           skipped: int, events: int, last_event_seq: int},
  live:   {next_task: int|null, completed: int, blocked: int,
           skipped: int, last_event_seq: int}
}
```

Field ordering inside objects is canonical-JSON-irrelevant (keys sorted at
hash time); the KEY SET is the parity contract across Python/Rust/MCP/CLI.

## 4. Check definitions (exact)

1. **state_vs_events (G1, FATAL)** — replay events via the exact shipped
   replay rules; compare `next_task`, `completed[]`, `blocked[]`,
   `skipped[]`, `last_event_seq` element-wise against live state.
   Any difference ⇒ status fatal, `fields` lists diverging keys, `detail`
   names first divergence (e.g. `"next_task live=105 replay=104"`).
2. **event_seq (G2, FATAL)** — events must have contiguous seq `1..N`;
   `live.last_event_seq == N`. Duplicate/gap/out-of-order ⇒ fatal with
   first offending index in detail.
3. **pointer_range (G5, FATAL)** — after replay: `next_task` must not point
   at a completed or currently-blocked id; `next_task > total_tasks` is
   legal ONLY as `null` (end of ledger).
4. **evidence (G3+G4, WARNING-only, never fatal)** —
   `missing`: completion events whose referenced evidence paths do not
   exist relative to tasks dir (empty evidence list ⇒ attested-none, NOT a
   finding — legacy rows predate evidence arrays);
   `orphans`: `*-completion.md` stub files with no matching completed id.

## 5. Error cases

| Case | Behavior |
|---|---|
| Corrupt event line mid-file | loud `ValueError` from existing `read_events` (unchanged) — surfaced as `{ok:false,error}` envelope; NO partial findings invented |
| State file unreadable/oversized | same loud error class (existing caps) |
| Missing state file | fatal-class error result `{ok:false}` — validate cannot run without a baseline; recovery hint string mentions `task rebuild` |
| Stray operand / unknown flag | usage refusal (audited), exit 2-class semantics per surface |

## 6. Persistence & audit effects

- **Persistence: NONE.** Validate writes nothing anywhere (report-only).
- **Audit: exactly one honest audit row per invocation**, including refusals
  (ADR-0035 §F-2 convention): tool `aios.task` / command
  `task.validate`, outcome ok|refused|error, c_flags `{c4:true}` only.
- **Gate:** read-only like `status|check|metrics` ⇒ **no PEP grant
  required** (D1/D2 decision). It must remain grant-free so recovery can be
  assessed under a broken-permission incident.

## 7. Surface contracts

- **Python reference** `tools/task_ledger.py validate` → prints JSON, exit 0.
- **Rust ship path** `aiosh task validate` → routes through `TaskCall`
  validation (needs_task_id=false), executes `ledger::validate_state`.
- **Rust MCP** `aios.task action:"validate"` → dispatch::recorded_call,
  read-only require_grant=false; schema violation (-32602) rules unchanged.
- **CLI parse rule:** `validate` takes no operand (parity with metrics).
- Cross-substrate: identical findings key set; matrix-suite extension pins
  Python↔Rust agreement on an intentionally drifted sandbox.

## 8. Acceptance mapping

- Happy path: green repo validates `consistent:true` with all checks ok.
- Failure path: seeded-drift sandbox reports fatal G1 with field list;
  corrupted-tail event log surfaces loud error; missing-state errors.
- Audit effects: every invocation appends exactly one row; chain verifies.

## 9. Out of scope (explicit)

Auto-healing, remote/NFS multi-host locking (L1), cryptographic signing of
events, changing rebuild semantics or its lock-free property.
