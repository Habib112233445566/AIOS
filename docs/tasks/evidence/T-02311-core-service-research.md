# T-02311: Audit Chain Extensions Core Service Research

## Objective
Establish architectural facts, operational constraints, and prior art for the Audit Chain Extensions core service (`audit_chain_service.rs`).

## Facts vs Assumptions

### Facts
1. **Underlying Storage**: Audit rows reside in SQLite WAL table `audit_ring` (and rotated compressed segment archives). Extension columns (`provenance_json`, `causal_links_json`, `signature_json`, `extensions_json`) store structured metadata serialized via canonical JSON.
2. **Cryptographic Binding**: In `ExtendedAuditRow`, the SHA-256 hash covers the previous row hash (`prev_hash`) plus canonical JSON representation of base fields, provenance, causal links, and extension dictionaries. Any tampering with metadata invalidates `hash`.
3. **Causal Graph Structure**: `AuditCausalLink` specifies `parent_event_hash` and `causality_type`. Because parent events precede child events in physical wall-clock time and append order, the causal graph forms a Directed Acyclic Graph (DAG) rooted at initial trigger events or genesis.
4. **Existing Service Conventions**: AIOS core services encapsulate business logic with typed inputs/outputs, explicit validation bounds, and standard error envelopes without raw unhandled exceptions.

### Assumptions
1. High-frequency queries will inspect execution by `session_id`, `trace_id`, and `parent_event_hash`.
2. Lineage tracing must enforce a hard recursion depth limit (e.g. `MAX_LINEAGE_DEPTH = 64`) to prevent denial-of-service in circular or deeply linked graphs.
3. Signature verification requires validating that `AuditSignature::signature` was generated by `public_key` over the row's `hash`.

## Prior Art & Standards
- **W3C TraceContext (RFC / Recommendation)**: Defines format for `trace_id` (16 bytes hex) and `span_id` (8 bytes hex).
- **PROV-O (W3C Provenance Ontology)**: Models causal entities, activities, and agents linked via derivation and delegation.
- **Git Commit Graph & Merkle DAGs**: Causal parent linking where each node cryptographically commits to its parents' hashes.
- **Ed25519 / RFC 8032**: High-speed public-key signatures ensuring message authenticity and integrity.

## Decisions Needed Prior to Implementation
1. **Service Architecture**: Encapsulate the core operations in a `AuditChainService` struct operating over an `AuditRing` or path.
2. **Lineage Traversal**: Provide depth-bounded breadth-first search (BFS) backwards for ancestry and forward for causal descendants.
3. **Filtering Query API**: Provide structured `AuditQueryFilter` supporting `session_id`, `trace_id`, `parent_hash`, `actor`, and time windows.
