# T-00112 — CI Smoke Orchestration / data model: SPECIFICATION

Date: 2026-08-23 · Status: SPEC v1.0 (implements D1–D5 from
`docs/tasks/evidence/T-00111-research.md`). Reviewable without the
implementation.

## 1. Feature summary

A typed, ordered **suite registry** and **result/summary record schemas**
for CI smoke orchestration. AIOS-specific conventions (marked per task
instructions); timestamps follow the repo-wide `%Y-%m-%dT%H:%M:%SZ` UTC
form; JSON only (no TAP/JUnit emission in this epic).

## 2. Interfaces reused vs new

| Reused | Why |
|---|---|
| `PASS:`/`FAIL:` + `[✓]/[✗]` console convention | human surface stays identical |
| `/tmp/aiosh-ci-<name>.log` naming | existing logs remain discoverable |
| Env-knob style (`AIOSH_*`, loud invalid errors) | parity with `AIOSH_LEDGER_*` |
| Additive-only stable key rule | metrics precedent (T-00082) |

| New (`tools/ci_suites.py`) | Shape |
|---|---|
| `SuiteDef` TypedDict | `{name: str, command: list[str], timeout_s: int}` |
| `SUITES: list[SuiteDef]` | exactly the 19 bash invocations, same order, same commands, per-suite timeouts (default 900 s; rust_smoke 1800 s) |
| `SUITE_NAMES: tuple[str, ...]` | derived; order = execution contract |
| `ResultRecord` TypedDict | §3 schema |
| `RunSummary` TypedDict | §3 schema |

## 3. Record schemas (stable ADDITIVE-only key sets)

```
ResultRecord = {
  "suite": str,            # registry name
  "index": int,            # 0-based position; ORDER IS CONTRACT
  "status": "pass"|"fail"|"timeout"|"error",
  "exit_code": int|null,   # null for timeout
  "duration_ms": int,
  "started_at": str,       # ISO-8601 Z
  "finished_at": str,
  "log_path": str          # /tmp/aiosh-ci-<name>.log
}

RunSummary = {
  "tool": "aios-ci-orchestrator",
  "schema_version": 1,
  "started_at": str,
  "finished_at": str,
  "total": int, "passed": int, "failed": int,   # failed == non-pass
  "all_pass": bool,
  "results": [ResultRecord, ...]
}
```

Status mapping: rc==0 → pass; rc!=0 → fail; subprocess.TimeoutExpired →
timeout (exit_code null); OSError spawning → error (exit_code null).
`failed := total - passed`.

## 4. Inputs / outputs

- Input: none beyond environment (`AIOSH_CI_RESULTS`; optional override of
  the summary artifact path). Registry itself is static data.
- Output (data-model level): `build_result_record(...)` pure constructor
  with validation; `write_summary(summary, path)` atomic writer
  (tmp + os.replace + fsync, mirroring ledger save_state_atomic).
- Invalid inputs to constructors raise `ValueError` naming the field
  (loud-error rule).

## 5. Error cases

| Case | Behavior |
|---|---|
| Duplicate suite name in registry | ValueError at import time (fail at load, never mid-run) |
| Empty command / non-list command | ValueError at import time |
| Non-monotonic index supplied to build_result_record | ValueError |
| Unwritable artifact path | OSError propagates from write_summary AFTER tmp cleanup (no orphan temp files) |
| Bad AIOSH_CI_RESULTS (empty string) | treated as unset → default path (env knobs elsewhere reject empties only when numeric; documented divergence here: path knobs accept any non-empty string) |

## 6. Persistence & audit effects

- Data model itself persists NOTHING at import; `write_summary` is the
  single persistence primitive (atomic replace; fsync'd tmp before rename).
- No audit-ring interaction in THIS epic (host CI tooling, not an MCP
  tool). If a future core-service epic exposes orchestration via
  `aios.*` tools, the classifier→PEP→audit gate applies THEN.
- Sequential-execution contract recorded IN DATA: `index` + registry
  order; consumers must not reorder.

## 7. Acceptance mapping

- Happy path: import succeeds; SUITES has 19 unique names matching
  run_all_smokes.sh 1:1; constructing records + writing/loading a summary
  round-trips byte-stable key sets.
- Failure path: duplicate names / empty commands rejected at import;
  invalid status/index rejected by constructors; timeout/error statuses
  constructible with exit_code null.
- Audit effects: N/A (documented §6) — no state-changing system surface.
