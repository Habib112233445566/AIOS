# T-00122 — CI Smoke Orchestration / core service: SPECIFICATION

Date: 2026-08-23 · Status: SPEC v1.0 (implements D1–D5 from
`docs/tasks/evidence/T-00121-research.md`). Reviewable without the
implementation.

## 1. Feature summary

`tools/ci_service.py` — a read-only CLI service over the CI run-summary
artifact produced by `tools/ci_run.py`. AIOS-specific conventions
(marked); no upstream standard claimed.

## 2. Interfaces reused vs new

| Reused | Why |
|---|---|
| `RunSummary`/`ResultRecord` TypedDicts + `RESULTS_PATH` + `SUITE_NAMES` | `tools/ci_suites.py` — single source; service imports, never redefines |
| `AIOSH_CI_RESULTS` env contract | producer/service parity |
| Loud field-naming errors; exit-code discipline | repo-wide convention |

| New | Shape |
|---|---|
| `load_summary(path) -> RunSummary` | strict validator (§4) |
| `human_report(summary) -> str` | stable line format (§5) |
| `failure_rows(summary) -> list[ResultRecord]` | status != pass |
| CLI: `show | failures | check` | §6 |

## 3. Inputs / outputs

- Input: artifact path via `--file PATH` (highest precedence) else
  `AIOSH_CI_RESULTS` else default `/tmp/aiosh-ci-results.json`.
  No other operands; unknown flags are usage errors (exit 2).
- Output: stdout text per action (§5/§6). Nothing is ever written by this
  service — read-only by contract.

## 4. Load-time validation (strict, loud)

Refuse (exit 2, message names the field) unless ALL hold:
1. JSON parses; top level is an object.
2. `schema_version == 1` (mismatch ⇒ explicit refusal, not best-effort).
3. Required keys exactly present (additive keys tolerated): `tool`,
   `schema_version`, `started_at`, `finished_at`, `total`, `passed`,
   `failed`, `all_pass`, `results`.
4. Arithmetic coherence: `passed + failed == total`; `all_pass ==
   (failed == 0 and total == len(SUITES))`.
5. Each result: `suite` in registry, `index == registry position`,
   `status` ∈ enum, timestamps end in Z, `exit_code` null iff
   status ∈ {timeout,error}.
6. Result indexes strictly increasing (order preserved).

## 5. Human report (`show`) — stable line formats

```
CI run <started_at> .. <finished_at>: PASS|FAIL
suites: <total> run, <passed> passed, <failed> failed
  [ok ] <index> <name> (<duration_ms> ms)
  [FAIL] <index> <name> (<duration_ms> ms) exit=<rc|-> log=<path>
```

`failures` prints only FAIL rows (plus the header lines); zero failures
prints `no failed suites`.

## 6. Actions & exit codes

| Action | stdout | exit 0 when | exit 1 when | exit 2 when |
|---|---|---|---|---|
| `show` | full report | always (after load) | – | load/usage error |
| `failures` | failure projection | always | – | load/usage error |
| `check` | one-line verdict | `all_pass` true AND complete run | gate failed | load/usage error |

`check` line: `ci-check: PASS (19/19 suites)` or
`ci-check: FAIL (17/19 suites, 2 failed)` — the counts come from the
artifact, never recomputed from the registry (report-only).

## 7. Error cases

| Case | Behavior |
|---|---|
| Missing artifact | exit 2 `summary artifact not found: <path>` |
| Unparseable JSON / missing key / bad version / incoherent math | exit 2 naming field (§4) |
| Unknown action / stray operand / unknown flag | exit 2 usage |
| Unreadable file (permissions) | exit 2 with OSError text |

## 8. Persistence & audit effects

NONE — strictly read-only host tooling (T-00112 §6 consistency). The
service never writes files, never mutates state, and has no MCP surface
in this epic.

## 9. Acceptance mapping

- Happy path: real artifact from `ci_run` renders via `show`; `check`
  exits 0 on the all-pass run.
- Failure path: seeded-fail artifact → `check` exit 1 with correct
  counts; `failures` lists exactly the failed rows.
- Audit effects: none (documented).
