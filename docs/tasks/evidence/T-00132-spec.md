# T-00132 — CI Smoke Orchestration / CLI surface: SPECIFICATION

**Date:** 2026-08-25
**Feature:** CI Smoke Orchestration CLI surface (`aiosh ci`)

## 1. Feature summary

The `aiosh ci` CLI command provides an operator-friendly native interface to the CI Smoke Orchestration core service. It parses, validates, and reports on the JSON artifact produced by the CI orchestrator, bridging the gap between raw data generation and actionable operational insights.

This specification documents the CLI surface that was natively integrated into the Rust stack (`aiosh-cli`) during the core service hardening phase.

## 2. Interfaces reused vs new

| Reused | Why |
|---|---|
| `aiosh` CLI executable | Single entry point for all AIOS operator interactions |
| Audit Ring (`aiosh_core::audit`) | Required for ADR-0035 §F-2 honest audit row emission |
| `AIOSH_CI_RESULTS` | Honors the same env contract as the orchestrator producer |

| New | Shape |
|---|---|
| `aiosh ci check` | Validates the run and exits 0 (all pass) or 1 (failures). Emits audit row. |
| `aiosh ci show` | Dumps the human-readable report. |
| `aiosh ci failures` | Filters and dumps only failed suites. |
| `--file PATH` flag | Explicitly overrides the summary artifact location. |

## 3. Inputs / Outputs

**Inputs:**
- Action positional argument: `check`, `show`, or `failures`.
- Flag: `--file <PATH>` (optional) overriding `$AIOSH_CI_RESULTS` and `/tmp/aiosh-ci-results.json`.

**Outputs:**
- `stdout`: Stable human-readable line formats for reports or verdicts.
- `stderr`: Loud, explicit usage errors or validation failures.

## 4. Error Cases & Exit Codes

| Case | Exit Code | Message / Effect |
|---|---|---|
| Success (`check` all pass, `show`, `failures`) | `0` | Action-specific stdout. `check` emits `success` audit row. |
| Gate failed (`check` with failing suites) | `1` | `ci-check: FAIL (<x>/<y> suites, <z> failed)`. Emits `failure` audit row. |
| Artifact missing / unreadable / >1MB | `2` | `ci-service: could not stat ...` or size cap exceeded. Emits `error` audit row. |
| Invalid JSON / Math incoherent | `2` | Detailed parse error text. Emits `error` audit row. |
| Invalid Action / Missing Flags | `2` | `usage: aiosh ci <show|failures|check> [--file PATH]` to stderr. |

## 5. Persistence & Audit Effects

**Persistence:**
The CLI surface is strictly read-only regarding the filesystem; it never mutates the artifact or writes new state files.

**Audit Effects (AIOS-specific):**
Per ADR-0035 §F-2, all invocations of the `aiosh ci check` gating command (and any load failures) result in the emission of an **honest audit row** to the system's SQLite WAL. The emitted row uses the `aiosh` tool namespace with the `ci check` command, capturing the `file` target in the arguments payload, and mapping the outcome to `success`, `failure`, or `error`.
