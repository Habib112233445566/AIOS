# Specification: PEP Decision Engine Recovery & Validation (T-02192)

## 1. Scope & Objective
This specification defines the formal contract, data structures, invariants, error codes, and behavioral guarantees for the PEP Decision Engine Recovery & Validation subsystem (`aiosh_core::pep_recovery`).

---

## 2. Invariants (`PEPRECV1..PEPRECV6`)

| Invariant | Name | Formal Rule |
|---|---|---|
| **`PEPRECV1`** | **Multi-Level Validation Hierarchy** | Every store is validated across 4 sequential stages: (1) Path & File Hygiene, (2) Syntactic/JSON Integrity, (3) Rule Semantic Constraints, (4) Service Capacity Bounds ($N \le 5,000$). |
| **`PEPRECV2`** | **Deterministic Validation Report** | Validation produces an immutable, machine-readable `PepValidationReport` detailing status, total rules scanned, valid count, corrupt count, issue list with codes and severities, and SHA-256 payload digest. |
| **`PEPRECV3`** | **Explicit Recovery Strategies** | Recovery executes under one of three deterministic strategies: `StrictFailClosed`, `SalvageValidRules`, or `DryRun`. No silent or ambiguous fallbacks. |
| **`PEPRECV4`** | **Non-Destructive Quarantine & Permissions** | Corrupted stores are never overwritten or deleted without prior backup. Quarantine files are copied to `<path>.bak.<timestamp>` with strict POSIX permissions (`0600`) on Unix. |
| **`PEPRECV5`** | **Dual Substrate Parity** | The recovery and validation engine is reachable via `aiosh pep validate` (CLI) and `aios.pep.validate` (MCP), producing identical diagnostic structures. |
| **`PEPRECV6`** | **Audit Trail Traceability** | Every validation scan, quarantine event, and salvage operation logs an immutable structured audit event into the AIOS SQLite ring buffer. |

## 3. Data Structures & Types

```rust
/// Severity of a validation issue.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "lowercase")]
pub enum PepIssueSeverity {
    Error,
    Warning,
}

/// A specific diagnostic issue identified during store validation.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct PepValidationIssue {
    pub rule_id: Option<String>,
    pub code: String,
    pub message: String,
    pub severity: PepIssueSeverity,
}

/// Comprehensive report generated after validating a PEP policy store.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct PepValidationReport {
    pub is_valid: bool,
    pub store_path: Option<String>,
    pub sha256_checksum: Option<String>,
    pub total_rules_scanned: usize,
    pub valid_rules_count: usize,
    pub corrupt_rules_count: usize,
    pub issues: Vec<PepValidationIssue>,
    pub inspected_at: String,
}

/// Recovery strategy mode.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize, Default)]
#[serde(rename_all = "snake_case")]
pub enum PepRecoveryStrategy {
    #[default]
    StrictFailClosed,
    SalvageValidRules,
    DryRun,
}

/// Result of an executed recovery operation.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct PepRecoveryResult {
    pub success: bool,
    pub strategy: PepRecoveryStrategy,
    pub original_path: String,
    pub quarantine_path: Option<String>,
    pub rules_salvaged: usize,
    pub rules_dropped: usize,
    pub validation_report: PepValidationReport,
    pub message: String,
}
```

## 4. Error Codes

| Error Code | Meaning |
|---|---|
| `PEPRECV_ERR_IO` | Filesystem read/write error, missing directory, or permission failure |
| `PEPRECV_ERR_PATH_TRAVERSAL` | Path contains `..`, control characters, or exceeds 1024 characters |
| `PEPRECV_ERR_FILE_SIZE` | Policy file exceeds maximum allowed size (10 MiB) |
| `PEPRECV_ERR_PARSE` | JSON syntax malformed or unclosed tokens |
| `PEPRECV_ERR_RULE_SYNTAX` | Individual rule missing required fields or invalid types |
| `PEPRECV_ERR_DUPLICATE_ID` | More than one rule shares the same identifier |
| `PEPRECV_ERR_CAPACITY` | Rule count exceeds maximum limit (5,000 rules) |
| `PEPRECV_ERR_CHECKSUM` | Computed SHA-256 does not match declared integrity digest |

## 5. Substrate Interfaces

### 5.1 CLI Command
```bash
# Validate policy store
aiosh pep validate <store_path> [--json]

# Validate and salvage valid rules
aiosh pep validate <store_path> --salvage [--json]
```

### 5.2 MCP Tool (`aios.pep.validate`)
```json
{
  "name": "aios.pep.validate",
  "arguments": {
    "store_path": "path/to/pep_policies.json",
    "strategy": "salvage_valid_rules"
  }
}
```
