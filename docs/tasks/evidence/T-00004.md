# T-00004 — Create fail-fast CI runner

**Completed:** 2026-08-21

## Acceptance criteria
- [x] `bash ci/run_all_smokes.sh` exits 0 with all suites PASS.

## What was built

`ci/run_all_smokes.sh` — a sequential, fail-fast runner:

- `set -euo pipefail`; each suite runs with its own log under
  `/tmp/aiosh-ci-<name>.log`; the first failing suite prints its last
  40 log lines and aborts the run.
- Per-suite PASS/FAIL summary and a final `== ALL N SMOKE SUITES PASS ==`.
- Order: cheap/pure first, heavy/integration last.
- The Rust rewrite is the primary implementation, so `rust_smoke`
  (`code/aiosh-rust/ci/rust_smoke.sh`: build + 45 unit tests + MCP stdio
  wire contract + CLI status) runs FIRST; the legacy TS/Python suites
  follow to pin the cross-substrate contract.

## Note

The first full run FAILED on `mcp_smoke` with
`ModuleNotFoundError: No module named 'aiosh_mcp'` because the legacy TS
CLI shells out to `python3 -m aiosh_mcp.sandbox` for `aiosh run`.
Root cause: the editable install from T-00002 was not present in this
environment.

**Resolution (2026-08-21, same day):** the TS CLI now resolves the
**Rust sandbox binary** (`code/aiosh-rust/aiosh-sandbox`) first and only
falls back to the Python shim if the binary is missing — so `mcp_smoke`
passes **without the Python package installed** (proven by running the
suite with `aiosh_mcp` uninstalled; the `rust_smoke` CI suite asserts
`aiosh run` emits `sandbox_applied` via the Rust binary). The remaining
legacy suites still import `aiosh_mcp` for their own Python-side checks,
so `pip install -e code/aiosh-mcp` is still part of the full CI run for
THOSE suites.
