## 1. Overview
- **Task ID**: `T-01851`

- **Goal**: Research automated test architecture, cross-surface verification, hermetic test fixtures, and define invariants `NTEST1..NTEST6`.

---

## 2. Facts vs. Assumptions

### Facts
1. The Network Bootstrap epic spans five interrelated subsystems:
   - Data Model (`network.rs`): `NetworkInterface`, `Route`, `DnsConfig`, `NetworkState`.
   - Core Service (`network_service.rs`): `NetworkService` with `sysfs`, `procfs`, `resolv.conf` parsing.
   - CLI Surface (`aiosh-cli`): `cmd_network` (`list`, `show`, `routes`, `dns`, `state`, `up`, `down`).
   - MCP/API Surface (`aiosh-mcp`): 7 MCP tools (`aios.network.*`) dispatched via `recorded_call`.
   - Configuration (`network_config.rs`): `NetworkConfig` with persistence and env ingestion.
2. In production Linux environments, sysfs (`/sys/class/net`), procfs (`/proc/net`), and resolv.conf (`/etc/resolv.conf`) are read-only or kernel-managed.
3. Network link state mutation (`up`, `down`) requires `CAP_NET_ADMIN` privileges or mock abstraction.
4. Unit and smoke tests already exist individually for each component, but cross-cutting end-to-end automated tests are needed to ensure complete integration.

### Assumptions
1. All automated tests must run hermetically without requiring `root` or `CAP_NET_ADMIN` privileges.
2. Cross-surface parity (Core $\leftrightarrow$ CLI $\leftrightarrow$ MCP) can be verified by executing tests against identical mock filesystem fixtures.
3. Test fixtures can be cleanly created in temporary directories and passed via configuration/CLI flags/environment variables.

---

## 3. Decisions Needed & Invariant Formulation

### Invariants (`NTEST1..NTEST6`)
1. **`NTEST1` (Hermetic Isolation)**: Automated tests must run fully in isolated, mock filesystem environments without depending on or mutating host networking.
2. **`NTEST2` (Cross-Surface Parity)**: Snapshots generated by Core (`NetworkService::get_network_state()`), CLI (`aiosh network state --json`), and MCP (`aios.network.state`) must produce byte-identical or structurally identical canonical JSON.
3. **`NTEST3` (Fault & Corrupt Data Injection)**: Automated suites must inject malformed sysfs files, truncated procfs route tables, non-IP DNS directives, and path traversal attempts, asserting graceful failure handling with explicit error messages.
4. **`NTEST4` (Audit Trail Integrity)**: Consequential operations (`up`, `down`) must produce verified audit rows with classification verdicts and timestamps in the audit log.
5. **`NTEST5` (Configuration Integration)**: Test runs must verify that environment overrides (`AIOS_NETWORK_*`) properly redirect mock discovery paths and enforce bounds.
6. **`NTEST6` (Deterministic Resource Cleanup)**: All mock directories, files, and temporary test artifacts must be reliably deleted upon test completion, even on failure paths.
